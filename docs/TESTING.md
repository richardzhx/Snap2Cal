# 验证范围

## 本地已验证

- 144个动作的引用顺序、条件/循环闭合、配置位置、分享入口和请求编码。
- 密钥为空的分发文件；仅请求DeepSeek官方接口；没有写入提醒事项App。
- 固定结果的创建循环模拟：勾选/跳过、空标题、缺失时间、无效日期、闰日、跨年、时区和自定义日程长度。
- v1.4.0的默认提醒动作与导入配置都为`1 hour before`；模拟检查相同的相对时间。
- 日期正则曾与1900至2100年74,772组年月日组合比对通过。
- Mac原生快捷指令曾用虚构文本验证：配置中填写密钥、运行时输入密钥，两条路径均能读取并去除首尾空格。此过程未发送网络请求、未写入日历。
- 分发文件使用Apple快捷指令工具签名，并解包核对动作与导入配置。

## 真实设备反馈与范围

维护者在iPhone使用此前的RC2后反馈可以正常使用。v1.4.0基于该版本，只调整默认提醒、名称与文案，没有改变主流程。新默认提醒仍建议安装后检查一次。

没有开展多型号、多iOS版本或多日历账户的全面兼容性测试；没有以程序测试证明模型识别准确率，也没有自动验证实际通知送达。

## 人工验收建议

1. 安装后配置自己的密钥和可写入日历。
2. 分别使用截图分享、背面轻点运行。
3. 用`tests/fixtures`三张图片核对独立事项、缺时间和日期边界。
4. 三项只勾第一、第三项，检查只打开两张对应表单。
5. 修改标题、日期和时间，保存后检查日历内容与提醒是否一致。
6. 默认应为开始前1小时；为了尽快测试送达，可另外建短期测试日程、手选较近提醒，并实际等待通知。
7. 测试取消、重复运行、错误密钥、断网与权限拒绝；注意已保存事项不会回滚。

`tests/fixtures`下的三张输入测试图为虚构素材；README顶部展示样机使用维护者提供的三张真实iPhone截图，记录勾选、编辑和保存后的日历。截图中事项来自虚构测试图，部分提示文案来自较早版本，提前2小时提醒是自定义配置。它们不证明所有设备兼容或实际通知送达。
